## 2. Data model

### 2.1 ตารางอ้างอิงใหม่

```prisma
enum DepartmentKind {
  MAIN   // หน่วยงานหลัก
  SUB    // หน่วยงานย่อย (ทั้งสองแบบใช้เป็น "หน่วยงานที่เบิก" และ "หน่วยงานที่ใช้" ได้)
}

model Department {
  id        String         @id @default(uuid())
  name      String         @unique
  kind      DepartmentKind
  isActive  Boolean        @default(true) @map("is_active")
  @@map("departments")
}

model Building {
  id       String  @id @default(uuid())
  name     String  @unique
  isActive Boolean @default(true) @map("is_active")
  @@map("buildings")
}

model StorageLocation {
  id       String  @id @default(uuid())
  name     String  @unique
  isActive Boolean @default(true) @map("is_active")
  @@map("storage_locations")
}
```

- **ชื่อซ้ำใน Dropdowndata ถูกรวม:** หน่วยงานย่อยซ้ำกันเอง 5 ชื่อ และ 10 ชื่ออยู่ทั้งในรายการหลักและย่อย ชื่อที่อยู่ทั้งสองรายการจะเป็น `MAIN`
- **ชั้น** (19 ถึง 2, M, G, B1 ถึง B3) เป็นรายการคงที่ในโค้ดที่ FE และ BE ใช้ร่วมกัน ไม่ต้องเป็นตาราง
- **ปิดใช้งานแทนการลบ** (`isActive`) เพราะประวัติการเบิกยังต้องอ้างถึงค่าเหล่านี้
- **หมวดหมู่:** ใช้ "ประเภทอุปกรณ์" 4 ประเภทจาก Dropdowndata แทน 5 หมวดตัวอย่างใน seed ปัจจุบัน

### 2.2 วัสดุ

```prisma
enum TrackingType {
  QUANTITY  // ยอดรวม
  SERIAL    // รายชิ้น
}

model Material {
  // ... ฟิลด์เดิม (ยกเว้น location)
  brand             String?
  model             String?
  trackingType      TrackingType     @default(QUANTITY) @map("tracking_type")
  storageLocationId String?          @map("storage_location_id")  // แทน location (ข้อความ)
  units             MaterialUnit[]
}
```

- **unique ของวัสดุ** = ชื่อ + ยี่ห้อ + รุ่น (ไม่สนช่องว่างและตัวพิมพ์เล็กใหญ่) ใช้ตอน import
- **เปลี่ยน `trackingType` ไม่ได้**หลังจากมีรายการรับ-เบิกแล้ว

### 2.3 ชิ้นอุปกรณ์ (เฉพาะวัสดุ `SERIAL`)

```prisma
enum UnitStatus {
  IN_STOCK  // อยู่ในคลัง
  ISSUED    // เบิกออกไปแล้ว
  VOID      // ยกเลิก (มาจากรายการรับเข้าที่ถูกยกเลิก)
}

model MaterialUnit {
  id                String       @id @default(uuid())
  materialId        String       @map("material_id")
  serialNumber      String       @map("serial_number")   // unique แบบไม่สนตัวพิมพ์เล็กใหญ่ (index lower())
  isTempSerial      Boolean      @default(false) @map("is_temp_serial")
  status            UnitStatus   @default(IN_STOCK)
  storageLocationId String?      @map("storage_location_id")
  createdAt         DateTime     @default(now()) @map("created_at") @db.Timestamptz(3)
  movements         TransactionUnit[]
  @@index([materialId, status])
  @@map("material_units")
}

/** ชิ้นไหนอยู่ในรายการรับ/เบิกไหน */
model TransactionUnit {
  transactionId String  @map("transaction_id")
  unitId        String  @map("unit_id")
  remark        String? // เช่น ติดตั้งกับเครื่อง VJRNB0300 (มาจากคอลัมน์ "หมายเหตุ" ใน Excel)
  @@id([transactionId, unitId])
  @@map("transaction_units")
}
```

**กฎ (ห้ามละเมิด):**
- วัสดุ `SERIAL`: `currentQuantity` = จำนวนชิ้นที่ `IN_STOCK` เสมอ ต้องอัปเดตทั้งสองอย่างใน DB transaction เดียวกัน
- **รับเข้า:** สร้างชิ้นใหม่ตามจำนวน S/N ที่กรอก ถ้า S/N ซ้ำกับที่มีในระบบให้ปฏิเสธด้วย 409 `DUPLICATE_SERIAL`
- **เบิก:** เลือกชิ้นที่ `IN_STOCK` ตามจำนวนที่เบิกพอดี แล้วเปลี่ยนเป็น `ISSUED` แบบมีเงื่อนไข (`updateMany where status = IN_STOCK` แล้วเช็ก `count`) เพื่อกันคนสองคนเบิกชิ้นเดียวกันพร้อมกัน
- **ยกเลิกรายการเบิก:** ชิ้นกลับเป็น `IN_STOCK`
- **ยกเลิกรายการรับเข้า:** ทุกชิ้นของรายการนั้นต้องยัง `IN_STOCK` แล้วเปลี่ยนเป็น `VOID`
- **แก้ S/N ได้เฉพาะ ADMIN** (ใช้แก้ S/N ชั่วคราวเป็นของจริง) ส่วนชิ้นห้ามลบ

### 2.4 รายการรับ-เบิก (เพิ่มฟิลด์)

```prisma
model StockTransaction {
  // ... ฟิลด์เดิม
  // รับเข้า (IN)
  fiscalYear              Int?    @map("fiscal_year")      // ปีงบประมาณ พ.ศ. เช่น 2568
  projectName             String? @map("project_name")     // ชื่อโครงการ (TOR)
  // เบิก (OUT)
  requesterId             String? @map("requester_id")     // ผู้เบิกที่เป็นผู้ใช้ในระบบ
  requesterName           String  @map("requester_name")   // ชื่อที่แสดงเสมอ (ชื่อผู้ใช้ หรือชื่อที่พิมพ์)
  requestingDepartmentId  String? @map("requesting_department_id")  // MAIN หรือ SUB
  usingDepartmentId       String? @map("using_department_id")
  buildingId              String? @map("building_id")
  floor                   String?
  purpose                 String?                          // ระบบงานที่ใช้
  units                   TransactionUnit[]
}
```

- **`requesterName` เก็บทุกครั้ง** แม้เลือกผู้ใช้ในระบบ เพื่อให้ประวัติแสดงชื่อเดิมได้ แม้ผู้ใช้จะเปลี่ยนชื่อภายหลัง
- ในรายการ IN ให้ `requesterName` = ชื่อผู้บันทึก

## 3. API (เพิ่มเติมจาก v2.1 §4.3)

| Method | Path | Role | หมายเหตุ |
|---|---|---|---|
| GET | `/lookups` | ทุก role | `{ departments, buildings, floors, storageLocations }` ส่งรายการทั้งหมดในครั้งเดียว ใช้ทำ dropdown |
| GET | `/materials/:id/units` | ทุก role | `status`, `search` (S/N), แบ่งหน้า ใช้ตอนเลือก S/N ที่จะเบิก |
| GET | `/units` | ADMIN, STAFF | ค้นหา S/N ทั้งระบบ, `tempOnly=true` ดูเฉพาะ S/N ชั่วคราว ผลลัพธ์บอกวัสดุ, สถานะ, รายการเบิกล่าสุด (ผู้เบิก/หน่วยงาน) |
| PUT | `/units/:id` | ADMIN | แก้ `serialNumber` แล้วตั้ง `isTempSerial = false` อัตโนมัติ |
| POST | `/import/preview` | ADMIN | อัปโหลด .xlsx ได้ผลตรวจและข้อเสนอ (ดู §5) ยังไม่บันทึกอะไร |
| POST | `/import/commit` | ADMIN | บันทึกตามผลตรวจ + การตัดสินใจของ Admin ทำใน DB transaction เดียว |
| POST | `/import/receipt/preview` | ADMIN | นำเข้าของซื้อใหม่จากหน้ารับเข้า (§5.4) ตรวจอย่างเดียว ยังไม่บันทึก |
| POST | `/import/receipt/commit` | ADMIN | บันทึกรายการรับเข้าจากไฟล์ |
| GET | `/import/receipt/template` | ADMIN | ดาวน์โหลดไฟล์ตัวอย่าง .xlsx |
| CRUD | `/lookups/departments`, `/lookups/buildings`, `/lookups/storage-locations` | ADMIN (แก้ไข) | เพิ่ม, แก้ชื่อ, ปิดใช้งาน (Q4) |

**ปรับ endpoint เดิม:**
- `POST/PUT /materials`: เพิ่ม `brand`, `model`, `trackingType`, `storageLocationId` และตัด `location`
- `POST /inventory/transactions`:
  ```jsonc
  {
    "type": "IN" | "OUT",
    "note": "...",
    // IN
    "fiscalYear": 2568, "projectName": "วัสดุปลายเปิดปี 2568",
    // OUT
    "requesterId": "uuid",            // หรือ
    "requesterName": "ชื่อที่พิมพ์",     // (ADMIN/STAFF เท่านั้น, USER ถูกบังคับเป็นตัวเอง)
    "requestingDepartmentId": "uuid", // บังคับ, MAIN หรือ SUB
    "usingDepartmentId": "uuid",      // บังคับ
    "buildingId": "uuid", "floor": "3", "purpose": "Notebook นศพ",  // ไม่บังคับ
    "items": [
      { "materialId": "...", "quantity": 2 },                                  // QUANTITY
      { "materialId": "...", "serialNumbers": ["SN1", "SN2"] },                // SERIAL + IN
      { "materialId": "...", "unitIds": ["u1", "u2"], "remarks": { "u1": "VJRNB0300" } } // SERIAL + OUT
    ]
  }
  ```
  สำหรับวัสดุ `SERIAL` ระบบคำนวณ `quantity` จากจำนวน S/N หรือจำนวนชิ้นที่เลือก
- `GET /inventory/history`: เพิ่ม filter `requestingDepartmentId`, `usingDepartmentId`, `serial`
- **Error code ใหม่:** `DUPLICATE_SERIAL` (409), `UNIT_NOT_AVAILABLE` (400: ชิ้นที่เลือกถูกเบิกไปแล้ว)

## 5. Import จาก Excel

### 5.1 ขั้นตอน (หน้า "นำเข้าข้อมูล")

1. **อัปโหลด** ไฟล์ .xlsx ที่มีชีต "รายการ" และ "Dropdowndata" ตามรูปแบบของ `IT_Inventory.xlsx`
2. **ตรวจและแสดงตัวอย่าง:** ระบบอ่านไฟล์ทั้งหมดแต่ยังไม่บันทึก แล้วแสดง 4 แท็บ:
   - **สรุป:** จำนวนวัสดุ, ชิ้น, ล็อตรับเข้า และรายการเบิกที่จะถูกสร้าง
   - **วัสดุ:** ตาราง 172 รายการ พร้อมรหัสที่สร้างให้, หมวดหมู่ และวิธีติดตามที่เสนอ ซึ่ง Admin เปลี่ยนได้
   - **จับคู่หน่วยงาน/อาคาร:** ค่าเก่าที่ไม่อยู่ในรายการ (หน่วยงานที่เบิก 13 ค่า, หน่วยงานที่ใช้ 74 ค่า, อาคาร 1 ค่า) ให้เลือกค่าที่ตรงกัน หรือเลือก "ไม่จับคู่ เก็บในหมายเหตุ" (D14)
   - **ปัญหา:** แถวที่ต้องรู้ เช่น S/N ชั่วคราวที่จะถูกสร้าง หรือเบิกแล้วแต่ไม่มีผู้เบิกหรือวันที่ (3 แถว)
3. **ยืนยัน:** บันทึกทั้งหมดใน DB transaction เดียว ถ้าผิดพลาดตรงไหนจะไม่บันทึกอะไรเลย แล้วแสดงรายงานผลให้ดาวน์โหลด

**การนำเข้าเต็มรูปแบบ (รวมประวัติการเบิก) ทำได้ครั้งเดียว** ตอนที่ระบบยังไม่มีวัสดุ ส่วนของที่ซื้อเพิ่มภายหลังให้นำเข้าจากหน้ารับเข้าตาม §5.4

### 5.2 กฎการแปลงข้อมูล

| ข้อมูลใน Excel | แปลงเป็น |
|---|---|
| Dropdowndata | หน่วยงาน (MAIN/SUB), อาคาร, สถานที่เก็บของ และหมวดหมู่ (ประเภทอุปกรณ์ 4 ค่า) |
| ชื่อ + ยี่ห้อ + รุ่น | วัสดุ 1 รายการ (รวมชื่อที่ต่างกันแค่ช่องว่าง เช่น "หัวปกป้องและถนอมหัวแลน" กับ "หัวปกป้อง และถนอมหัวแลน") |
| รหัสวัสดุ | Excel ไม่มี (SKU ว่าง) ระบบสร้างตามประเภท: `HW-001` (Hardware), `NET-001` (เครือข่าย), `PER-001` (ต่อพ่วง), `CON-001` (สิ้นเปลือง) |
| หน่วยนับ / จุดสั่งซื้อ | "ชิ้น" / 5 (D13) |
| สถานที่เก็บของ | สถานที่เก็บของวัสดุ ใช้ค่าที่พบบ่อยที่สุด เพราะมี 2 วัสดุที่เก็บ 2 ที่ ส่วนวัสดุรายชิ้นจะเก็บสถานที่ของแต่ละชิ้นด้วย |
| ปีงบประมาณ + ชื่อโครงการ | **รายการรับเข้า 1 รายการต่อ (ปีงบ, โครงการ, วัสดุ)** วันที่ = 1 ต.ค. ของปีงบนั้น (เช่น ปีงบ 2568 → 2024-10-01) ราคาต่อหน่วยจาก Excel |
| แถวที่ "เบิกแล้ว" | **รายการเบิก** จัดกลุ่มตาม วันที่ + ผู้เบิก + หน่วยงานที่เบิก + หน่วยงานที่ใช้ + อาคาร + ชั้น + ระบบงาน (ประมาณ 358 รายการ) เวลา 09:00 · `requesterName` = ชื่อใน Excel (ผู้บันทึก = Admin ที่ import) |
| หมายเหตุ | วัสดุรายชิ้น → `remark` ของชิ้นนั้น · วัสดุยอดรวม → ต่อท้ายหมายเหตุของรายการ |
| เลขอ้างอิง | `TXN-<วันที่ของรายการนั้น>-NNN` ตามวันที่จริงในอดีต |

### 5.3 Serial Number

**S/N ที่ใช้ได้:** ไม่ว่าง, ไม่ใช่ `-` และไม่ซ้ำกับแถวอื่นในไฟล์ ค่าที่ซ้ำหลายแถวไม่ใช่ S/N เช่น รหัสรุ่น `US-6621IW` ×100 หรือบาร์โค้ดสินค้า `8859596018072` ×30 (รางปลั๊กไฟ) และ `8850304016977` ×10 (สเปรย์ 3M)

> ตัวเลข 13 หลักที่ไม่ซ้ำกันถือเป็น S/N จริง เช่น สาย USB UGREEN แถว 1286–1290 และ Tp-Link UE300C แถว 4450, 4452, 4457 (ร่างแรกเคยตัดทิ้งทั้งหมด ซึ่งผิด)

**วิธีติดตามที่ระบบเสนอ:**

| S/N ของวัสดุนั้น | จำนวน (จากไฟล์ปัจจุบัน) | ข้อเสนอ |
|---|---|---|
| มีครบทุกชิ้น | 87 วัสดุ / 2,379 ชิ้น | `SERIAL` |
| ไม่มีเลย | 76 วัสดุ / 1,862 ชิ้น | `SERIAL` + S/N ชั่วคราวทุกชิ้น (เดิม `QUANTITY` เปลี่ยน 2026-10-25) |
| มีบางชิ้น | 9 วัสดุ / 250 ชิ้น | `SERIAL` + **S/N ชั่วคราว** ให้ชิ้นที่ไม่มี (D15) |

**S/N ชั่วคราว (D15):** `<S/N จริงของชิ้นที่ "ลำดับ" ใกล้ที่สุดในวัสดุเดียวกัน>-TEMP-SN-<เลขรันในวัสดุนั้น 2 หลัก>`
เช่น `172447520979-TEMP-SN-01` ถ้าวัสดุไม่มี S/N จริงเลยใช้รหัสวัสดุแทน เช่น `NET-021-TEMP-SN-01` จะมี `isTempSerial = true` ค้นหาได้จากหน้า "ค้นหา S/N" → "เฉพาะ S/N ชั่วคราว" และ Admin แก้เป็น S/N จริงได้

ถ้า Admin เปลี่ยนวัสดุไหนเป็น `QUANTITY` ในหน้าตัวอย่าง จะไม่สร้าง S/N ให้วัสดุนั้น

### 5.4 นำเข้าของที่ซื้อใหม่ จากหน้า "รับเข้า" (ADMIN เท่านั้น) · Q1

ใช้ตอนซื้อของล็อตใหม่ เพื่อไม่ต้องกรอก S/N ทีละชิ้น

- **ปุ่ม "นำเข้าจากไฟล์"** แสดงเฉพาะ ADMIN ในหน้ารับเข้า (API: `POST /import/receipt/preview` และ `/import/receipt/commit`, ADMIN เท่านั้น)
- **ไฟล์:** รูปแบบคอลัมน์เดียวกับชีต "รายการ" มีปุ่มดาวน์โหลดไฟล์ตัวอย่าง (template) ใช้คอลัมน์: ชื่อวัสดุ, ยี่ห้อ, รุ่น, S/N, ประเภทอุปกรณ์, ปีงบประมาณ, ราคาต่อหน่วย, ชื่อโครงการ, สถานที่เก็บของ
- **จับคู่วัสดุ:** ด้วยชื่อ + ยี่ห้อ + รุ่น
  - **มีอยู่แล้ว:** ใช้วิธีติดตามเดิมของวัสดุนั้น
  - **ยังไม่มี:** แสดงเป็น "วัสดุใหม่" ในหน้าตัวอย่าง (สร้างรหัสให้, หน่วย "ชิ้น", จุดสั่งซื้อ 5, เสนอวิธีติดตามตาม §5.3) และ Admin แก้ได้ก่อนยืนยัน
- **S/N:** ซ้ำกับที่มีในระบบหรือซ้ำกันในไฟล์จะแสดงเป็นแถวที่มีปัญหาและไม่ให้ยืนยันจนกว่าจะแก้ ส่วนวัสดุรายชิ้นที่บางชิ้นไม่มี S/N จะได้ S/N ชั่วคราวตาม §5.3
- **ผลลัพธ์:** รายการรับเข้า 1 รายการต่อ (ปีงบประมาณ, โครงการ) วันที่ = วันที่นำเข้า บันทึกทั้งหมดใน DB transaction เดียว
- **ไฟล์นี้รับเข้าอย่างเดียว:** แถวที่สถานะ "เบิกแล้ว" จะถูกแจ้งเป็นปัญหา

## 6. ผลกระทบกับระบบที่มีอยู่

- **Migration เพิ่มตารางและคอลัมน์ใหม่เท่านั้น:** DB จริงตอนนี้มีแค่ Admin + 5 หมวดตัวอย่าง จึงไม่มีข้อมูลต้องย้าย

- **ทำได้ภายหลัง:** "มูลค่าคลัง" เพราะ Excel มีราคาต่อหน่วย 90% ของแถว
